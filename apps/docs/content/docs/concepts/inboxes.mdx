An inbox is one email address. Create as many as your plan allows: one per agent, per task or per customer.

```ts
const inbox = await send0.inboxes.create({
  name: "procurement-agent",          // → procurement-agent@send0.email
  display_name: "Procurement Agent",   // sender name recipients see
  send_policy: "reply_only",           // open | reply_only | approval
  metadata: { team: "ops", run: 42 },  // your own labels, up to 20 keys
});
```

## Addresses

- Addresses are case-insensitive: `Research-Agent@` and `research-agent@` are the same inbox.
- **Plus-addressing:** mail to `procurement-agent+po4471@send0.email` lands in `procurement-agent` with `tag: "po4471"`. Use it to tell tasks apart without creating inboxes.
- Reserved names can't be used: `postmaster`, `abuse`, `admin`, `support`, `noreply`, `security`, `billing` and similar.
- Mail to an address that doesn't exist is refused while the sender's server is still connected (`550 5.1.1`), so senders get an immediate, clear bounce.

## Send policies

| Policy | Behaviour |
|---|---|
| `reply_only` | Can only send to addresses that have already emailed this inbox. **Free accounts are always reply-only.** |
| `open` | Can send to anyone (paid plans, subject to limits and the acceptable use policy). |
| `approval` | Every outgoing message becomes a [draft](/concepts/drafts) that a person approves. |

Change it any time:

```ts
await send0.inboxes.update(inbox.id, { send_policy: "approval" });
```

## Deleting

```ts
await send0.inboxes.delete(inbox.id); // needs an admin key
```

Mail to a deleted inbox is refused from then on. The address is **never given to anyone else**, so a deleted agent's mail can't land with a stranger.

## Limits

The free plan includes 5 inboxes. Deleted inboxes don't count. Creating one more returns `402 plan_limit_reached`.
